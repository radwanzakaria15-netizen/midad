# مِداد | مساحة الأستاذ والمتعلم

## التشغيل
واجهة عربية RTL. بيانات الأستاذ تحفظ محلياً، ويمكن مزامنتها عبر Cloudflare Pages Functions + D1 بعد إعداد Cloudflare. تسجيل دخول الأستاذ ما زال عبر Supabase في هذه المرحلة؛ بيانات مساحة العمل وسجلات المتعلمين المنشورة تحفظ في D1.

## إعداد Cloudflare Pages + D1
1. أنشئ قاعدة D1 باسم `midad` في حساب Cloudflare.
2. انسخ معرّف القاعدة إلى `database_id` في `wrangler.toml`.
3. نفّذ ملف `migrations/0001_midad.sql` على قاعدة D1 من لوحة Cloudflare أو عبر Wrangler.
4. اربط هذا المستودع بمشروع Cloudflare Pages، واجعل مجلد الإخراج `.`.
5. أضف متغيري البيئة في إعدادات Pages (Production وPreview):
   - `SUPABASE_URL`: رابط مشروع Supabase الحالي.
   - `SUPABASE_ANON_KEY`: مفتاح النشر العام، وليس service role.
6. انشر المشروع على Cloudflare Pages. GitHub Pages لا يشغّل مجلد `functions`.
7. افتح موقع Cloudflare Pages وسجّل دخول الأستاذ. عند تحميل المساحة أو حفظها، تُزامَن مساحة الأستاذ وتُحدّث سجلات المتعلمين المنشورة في D1.

## دخول المتعلم
- يدخل المتعلم برقم التعريف ذي 6 أرقام فقط.
- الواجهة تطلب `/api/student?code=XXXXXX` وتعرض البيانات المنشورة لذلك المتعلم من D1.
- تُعرض الدروس والأنشطة المعيّنة له أو لقسمه، والبرنامج، وملاحظات القسم، والنقاط المنشورة فقط.
- لأن الدخول يعتمد على رقم معروف فقط دون PIN، يستطيع أي شخص يعرف الرقم فتح البيانات المنشورة لذلك المتعلم. لا تنشر بيانات حساسة بهذه الطريقة.

## حدود المرحلة الحالية
- لم تتم إزالة Supabase Auth؛ ما زال مسؤولاً عن حساب الأستاذ والتحقق من الجلسة.
- ملفات المرفقات الكبيرة أو المخزنة بصيغة data URL تحتاج إلى ترحيل منفصل إلى Cloudflare R2.
- إنشاء قاعدة D1 وربط Pages وإضافة متغيرات البيئة والنشر خطوات داخل حساب Cloudflare، ولا ينفذها رفع الملفات إلى GitHub وحده.
- لا تضع مفاتيح سرية في ملفات الواجهة أو المستودع.
